# 팀 역할 분담 (Ownership)

> 리팩터링·재정비를 앞두고, 서로의 코드를 모르게 건드려 발생하는 사이드이펙트를 줄이기 위한 **페이지 단위 담당표**입니다.
> 팀원: 선아 / 소영 / 하은 / 영찬

---

## 분배 원칙

1. **한 기능(세로 슬라이스)은 한 사람** — "위시 시작/마무리", "인증/소셜로그인"처럼 같은 파일을 둘이 나눠 갖지 않는다.
2. **공유 인프라는 오너를 명시** — API client·토큰·webBridge·공통 UI·`consts`·`types`. 변경 PR은 오너 리뷰 필수.
3. **딥(좁고 깊은) 조각을 한 사람에게 몰지 않는다** — 인증/토큰 인프라 · 플레이 상태머신 · SSE/FCM 재연결은 LOC는 작아도 난도·파급력 최상. 서로 다른 사람에게 분산.

## 경계 요약

- **위시 + 소셜로그인** = 소영 (담기 · 목록 · 상세 · 위시→토너먼트 담기 · 로그인 진입/소셜 교환)
- **토너먼트** = `시작(start)` 버튼 기준 2분할
  - **시작 前 — 구성·소셜** (초대/참여/참여자/마감/시작) = **하은**
  - **시작 後 — 플레이·결과** (대진/결과/그룹) = **영찬**
- **알림·실시간(SSE/FCM)·웹뷰 브릿지** = 하은
- **토큰 인프라 · 계정 · 플랫폼 + 공동 리뷰** = 선아 (인터셉터·refresh·세션, 마이페이지, 공유 인프라 스튜어드십)
- **홈** = 소영 (허브: 위시담기 + 토너먼트 진입 런처)

> ⚠️ create 화면 안에 초대·참여자·마감·시작 등 **소셜 로직이 통째로 들어있어**, "준비 vs 소셜"로 나누면 한 화면을 둘이 건드리게 된다. 그래서 소셜을 create와 묶어 하은이, 실제 플레이는 영찬이 갖는다.

## 📄 페이지 단위 담당표

### 🟣 선아 — 토큰 인프라 · 계정 · 플랫폼 · 소셜로그인 (+ 공동 리뷰)

| 페이지 / 대상                                                                                  | 비고                                                     |
| ---------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `/` (스플래시)                                                                                 | 진입 시 인증 체크·리다이렉트                             |
| `layout.tsx` (루트)                                                                            | 앱 셸                                                    |
| **토큰 인프라** (`apis/client.ts`·`apis/server.ts` 인터셉터, `refreshClientToken`, `proxy.ts`) | refresh race · 401 재시도 · 세션 리다이렉트 (딥빌드 1개) |
| `/mypage` · `/mypage/edit` · `/mypage/withdraw` (+layouts)                                     | 마이페이지                                               |
| `/(legal)/privacy` · `/(legal)/terms`                                                          | 약관 (설정 영역)                                         |
| `/login` (+layout)                                                                             | 로그인 진입 · `getAuthUrl` · 게스트로그인 (소영 그대로)  |
| `/auth/callback/[provider]`                                                                    | 소셜 교환 (`postSocialLogin`) — 선아 공동 리뷰           |

### 🟢 소영 — 위시 + 홈

| 페이지 / 대상                     | 비고                                                          |
| --------------------------------- | ------------------------------------------------------------- |
| `/home`                           | 허브 (위시담기 + 토너먼트 진입 버튼)                          |
| `/archive` (+layout)              | 위시 목록                                                     |
| `/archive/wish/[id]` (+layout)    | 위시 상세 / 복구                                              |
| `/tournament/[id]/create/by-wish` | 위시 선택 UI — `WishCard`·`useGetWishlist` 재사용 (소영 이관) |

### 🟠 하은 — 토너먼트 구성·소셜 (시작 前)

| 페이지 / 대상                                                                                | 비고                                              |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| `/tournament/[id]/create` (+layout)                                                          | 구성·초대·참여자·마감·시작 = 소셜 대기실          |
| `/tournament/[id]/item/[itemId]` (+layout)                                                   | 아이템 편집                                       |
| `/invite/[id]`                                                                               | 초대 링크 진입 → 구성 참여                        |
| `/tournament/join/[id]`                                                                      | 참여 진입 → 구성 합류                             |
| `/notification`                                                                              | 알림 화면                                         |
| **실시간 SSE/FCM** (`useNotificationSSE`, `useFcmTokenSync`, `/api/notifications/subscribe`) | 재연결·백오프·푸시 토큰 (딥빌드) — 선아 공동 리뷰 |

### 🔵 영찬 — 토너먼트 플레이·결과 (시작 後)

| 페이지 / 대상                   | 비고                      |
| ------------------------------- | ------------------------- |
| `/tournament/[id]/loading`      | 시작 로딩                 |
| `/tournament/[id]/match`        | 대진 플레이 (딥 상태머신) |
| `/tournament/[id]/result`       | 결과                      |
| `/tournament/[id]/result/group` | 그룹 결과                 |
| `/play/[id]`                    | 플레이 링크 진행 진입     |

## ⚪ 공유 접점 (오너 + 상호 리뷰)

세로로 나눠도 완전히 안 겹치는 건 불가능하다. 남는 접점은 **오너를 정하고, 변경 시 상호 리뷰**로 관리한다.

| 대상                                                                                           | 오너           | 주 사용자                     | 메모                                                                                                          |
| ---------------------------------------------------------------------------------------------- | -------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `/tournament/[id]` (layout) + `_common`(`getTournament`, `deleteTournamentItem`)               | 선아           | 하은·영찬                     | 토너먼트 공용 데이터 척추 (시작 前/後 공통)                                                                   |
| `components/get-item-dialog` (위시 담기 엔진)                                                  | 소영           | 소영(홈/archive)·하은(create) | 인터페이스 변경 시 하은에 공지                                                                                |
| `create/by-wish` → `postTournamentItemsByWish` · `useGetTournament`                            | 하은/공용      | 소영                          | by-wish는 소영 소유지만 이 write API는 하은 소유 → 시그니처 변경 시 공지                                      |
| `/login`·`/auth/callback` (소영) ↔ 토큰 인터셉터/refresh (선아)                                | 소영·선아 공동 | 소영                          | **토큰 발급 시점이 seam** — 발급 前(소셜 교환)=소영, 發급 後(저장·갱신·인터셉터)=선아. 인증 변경 시 상호 리뷰 |
| `components/common/*`, `consts/route`·`consts/api`, `types/*`                                  | 선아           | 전원                          | 공통 UI·라우트·API 상수·도메인 타입                                                                           |
| `webBridge` **계약(프로토콜)** (`utils/webBridge`, `consts/webBridge`, `types/webBridge`)      | 선아           | 하은·소영                     | 계약은 선아 오너, **구현(FCM/SSE)은 하은**                                                                    |
| API client / 토큰 (`apis/client.ts`, `apis/server.ts`, `utils/refreshClientToken`, `proxy.ts`) | 선아           | 전원                          | 인터셉터·토큰 갱신 (파급력 최상)                                                                              |

## 🎯 각자의 딥 챌린지 (동아리 = 다들 어려운 거 하나씩)

볼륨이 아니라 **"좁고 깊은" 기술 난제**를 한 사람당 하나씩 명시. grunt work만 하는 사람이 없도록.

| 사람     | 딥 챌린지                                                                                         |
| -------- | ------------------------------------------------------------------------------------------------- |
| **선아** | 토큰 인터셉터 + refresh race + 세션 리다이렉트 (`client.ts`/`proxy.ts`) + 소셜 로그인 흐름 — 코어 |
| **소영** | 위시 무한스크롤 + optimistic update + 이미지 OCR 파이프라인                                       |
| **하은** | 실시간 SSE 재연결/백오프 + FCM 푸시 + 웹뷰 브릿지 + 게스트/초대 토큰 흐름                         |
| **영찬** | 토너먼트 대진 상태머신 + 결과 집계                                                                |

## 운영 규칙

- **경로별 오너십은 `CODEOWNERS`로 강제** — 해당 경로 PR에 오너가 자동 리뷰어로 배정되어, 남의 코드 변경이 자동 감지된다. (`create/by-wish/**` → 소영, `create/**` → 하은처럼 **더 구체적인 경로가 우선**)
- **공유 접점(⚪) 변경**은 오너 승인 전 머지 금지.
- **인터페이스(공유 훅/타입/상수) 변경**은 PR 설명에 영향받는 담당자를 멘션.
- 담당이 애매한 신규 코드는 이 문서의 경계 요약으로 판단하고, 그래도 모호하면 팀에 확인 후 이 표를 갱신한다.
